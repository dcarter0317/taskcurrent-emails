# TaskCurrent MJML -> GitHub Actions -> Cloudflare -> n8n starter

This ZIP contains only **new** configuration/build files. It does not replace or modify your existing MJML templates, components, or manual `test-n8n-webhook.yml` workflow.

## What the build does

1. Compiles the six root-level emails with MJML strict validation and includes enabled.
2. Writes compiled HTML to `dist/` plus a `dist/manifest.json` file listing filenames, sizes, and SHA-256 hashes.
3. In GitHub Actions, uploads `dist/` as a downloadable artifact.
4. For successful builds on `master`, sends a JSON event containing the build metadata to your existing Cloudflare-protected n8n production webhook.
5. Does **not** send any emails. It does **not** put full HTML email content into the webhook payload.

## Installation in your LOCAL repository (VS Code)

1. Copy the files from this ZIP into the root of your existing `taskcurrent-emails` repository, preserving `.github/workflows/build-mjml.yml` and `scripts/build-emails.cjs` directories.
2. Open a terminal in the local repository.
3. Run `npm install` to install MJML and generate a `package-lock.json`.
4. Run `npm run build:emails` to test all six templates locally.
5. Review generated HTML in `dist/`. (The `dist/` directory is Git-ignored.)
6. If compilation succeeds, commit the new files and the generated `package-lock.json`:

   ```bash
   git status
   git add .github/workflows/build-mjml.yml scripts/build-emails.cjs package.json package-lock.json .gitignore
   git commit -m "Add automated MJML build and n8n notification"
   git push
   ```

7. In GitHub Actions, open **Build TaskCurrent MJML Emails**. A push to `master` automatically runs it when relevant source/build files change; you can also use **Run workflow** manually.
8. Confirm the `taskcurrent-html-emails` artifact contains six `.html` files and a `manifest.json`.
9. Open your n8n `TaskCurrent - Email Build Webhook` workflow, select **Executions**, and inspect the most recent webhook's `body` for the `mjml.build.succeeded` event and six templates.

## Cloudflare & n8n

- The webhook destination is `https://n8n.dcartdevelopment.com/webhook/taskcurrent-email-build`.
- Your existing GitHub secrets `CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET` are referenced during the workflow. Do not put their values in the repository.
- Keep your existing n8n webhook **published**, method **POST**, path **taskcurrent-email-build**, and response **Immediately** for this phase.
- No changes are required to your existing Cloudflare Access policies or your manual webhook test workflow.
- The new notification payload is **build metadata only**; a later step can add artifact retrieval, rendering, and optional test sending.

## If validation fails

The build deliberately uses strict validation and **does not notify n8n** after a failed compile. Fix the errors in your MJML source and rerun. During repository review we noticed possible typos worth checking:

- `early_access_product_intro.mjml`: stray `z` immediately after `</mj-head>`.
- `demo_reminder.mjml`: stray `–-` immediately after one of the `</mj-text>` tags.

These typos are not automatically changed by this starter. The first local build will show whether they cause strict compilation errors, along with any other issues.

## Notes

- This starter pins `mjml@5.4.1` for repeatable behavior. A separate `package-lock.json` must be generated by `npm install` and committed before GitHub can run `npm ci`.
- MJML 5 requires an explicit setting to process `mj-include` tags; the build enables them.
- GitHub automatically injects `GITHUB_SHA`, `GITHUB_RUN_ID`, `GITHUB_REF_NAME`, and `GITHUB_REPOSITORY` in the workflow runner.
- Test sends, ESP integrations, and n8n transformations are intentionally not included yet.
